# Lessons Learned

## Hermes Laya Tools
- Always load configuration from environment variables (.env) with sane defaults.
- Zero external dependencies: use Python standard library (`urllib.request`, `json`, etc.) so it works out of the box in Hermes Python environment without requiring extra pip packages.
- Shadow mode must ensure zero mutation of `agent.tools` and zero prompt injection, while performing full Laya inference and detailed logging.
- When executing remote SSH commands, always specify proper timeouts (`-o ConnectTimeout=...`) and avoid piping unbounded network calls.
- **Hermes WebUI Settings Integration**: To render plugin settings in the Hermes Desktop / WebUI under "Настройки → Плагины", `plugin.yaml` must declare `config_schema` (Manifest v2). Saving settings in UI writes to `plugins.entries.<id>.settings` in `config.yaml`, which the plugin should read via `ctx.get_config(key)` for instant zero-restart updates.
- **Encoder Position Bias & Safe Decision Thresholds**: Encoder models like `laya-multilingual` suffer from position bias on binary choices (the first option can receive a spurious +3-5% probability boost). Never strip tools on raw argmax (`> 0.50`) with near-zero confidence. Enforce high safety thresholds (e.g. `direct_chat_threshold >= 0.75` and `min_confidence >= 0.15`) before stripping tools in an agent environment.
- **State Snippet Hygiene**: Strip system prompts, role headers, and slash command preambles (like `[/plan — plan mode]`) before sending state to Laya to avoid prompt pollution and tokenizer truncation.
- **Laya Training GPU0 VRAM Check & CPU Fallback**: When running `laya-train` on a server where the primary LLM (`ninfer-serve` / `coder390-27b`) occupies most of `gpu0` VRAM, always check free VRAM on `gpu0` first (or catch `CUDA out of memory`) and automatically switch `laya-train` to `--device cpu` (`--epochs 4 --micro-batch 4 --grad-accum 1 --shuffle-options`) so full encoder+head training completes reliably without OOM. Always document and enforce this rule inside the `laya-train` skill.
- **No Duplicate Rows in `train.jsonl` (`split_calibration` Leak Prevention)**: `laya-train` internally splits `calib_items` (`10%`) from `train.jsonl` via `split_calibration()`. Writing duplicate oversampled rows into `train.jsonl` leaks identical examples into both `train_items` and `calib_items`, breaking temperature calibration. Keep `train.jsonl` strictly deduplicated.
- **Backup Before Replace**: Any pipeline step that overwrites a model artifact (`laya-train --out` checkpoint, active GGUF in `/root/deepseek-harness/models/`) must first copy it to `<name>.<YYYYmmdd-HHMMSS>.bak` (keep last N). An earlier run overwrote the previous fine-tuned checkpoint and GGUF with no copy and the prior model was lost.
- **Primary Model Teacher Query (`enable_thinking: true` & `reasoning_effort: xhigh`)**: When querying the primary model (`andrei-router` / `coder390-27b` on `ninfer-serve`) to label or verify Laya routing decisions in `extract_and_label.py`, always pass top-level `"reasoning_effort": "xhigh"` and `"chat_template_kwargs": {"enable_thinking": True}` (do NOT put `reasoning_effort` inside `chat_template_kwargs`, as `ninfer-serve` returns HTTP 400 for `chat_template_kwargs.reasoning_effort`) with `max_tokens: 4096` and `timeout: 90s`.
