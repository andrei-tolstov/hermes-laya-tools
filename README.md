# hermes-laya-tools

Плагин умной двухуровневой маршрутизации и суточной категоризации инструментов (System 1 Decision Engine) для **Hermes Agent** на базе модели **Laya**.

Написан на **чистом Python** (без внешних зависимостей, используя стандартную библиотеку), поддерживает нативный жизненный цикл плагинов Hermes, структурированный JSONL-аудит всех обращений к Laya и новый режим **Shadow Mode**.

---

## 🎯 Назначение и возможности

При работе автономного агента в Hermes подключено множество инструментов (инструменты терминала, файловой системы, веб-поиска, MCP-серверы и т.д.). Передача десятков или сотен инструментов в основную LLM раздувает контекст, увеличивает стоимость токенов, замедляет инференс и приводит к галлюцинациям.

**hermes-laya-tools** решает эту проблему с помощью сверхбыстрого инференса Laya (~20–40 мс):

1. **Суточная категоризация инструментов (24h TTL)**:
   - Раз в 24 часа все доступные в сессии инструменты группируются по семантическим категориям (`filesystem`, `terminal_execution`, `web_and_search`, `browser_automation`, `code_and_git`, `devops_containers`, `external_messaging`, `general_utility`).
   - Результат кэшируется на диск в `~/.hermes/cache/laya_categories.json`.
   - Неизвестные или кастомные MCP-инструменты классифицируются батчем через Laya.

2. **Уровень 1 (Оценка контекста и гейткипинг)**:
   - Перед каждым запросом к основной нейросети Laya оценивает тип запроса:
     - `direct_chat` (приветствие, объяснение, теоретический вопрос) — инструменты **полностью отсекаются** (`tools = []`), экономя контекст и токены.
     - `execute_tools` — выбирается наиболее релевантная семантическая категория.

3. **Уровень 2 (Выборка Топ-10)**:
   - Формируется пул кандидатов из выбранной категории (с добором при необходимости до `max_tools`).
   - Если пул превышает лимит (по умолчанию 10), Laya ранжирует кандидатов и оставляет **ровно Топ-10** наиболее релевантных инструментов.

4. **👻 Режим Shadow Mode (`LAYA_MODE=shadow`)**:
   - Плагин выполняет полный цикл оценки: отправляет запросы в Laya, получает вероятности, вычисляет гипотетическое решение (direct_chat / отбор инструментов) и фиксирует полный аудит в лог-файл.
   - **Выдача и набор инструментов основной модели (`agent.tools`) остаются на 100% неизменными**. В чат не внедряются сторонние системные уведомления.
   - Позволяет безопасно тестировать и валидировать качество работы Laya на реальном трафике перед боевым включением.

5. **📊 Полный аудит запросов (JSONL)**:
   - Все запросы и ответы Laya логируются в `~/.hermes/logs/laya_requests.jsonl`.
   - Сохраняются: `timestamp`, `session_id`, `turn_id`, `mode`, `decision`, `winning_category`, `probability`, `selected_tools`, `available_tools`, `latency_ms`, `error`.

## ⚙️ Настройки в интерфейсе Hermes и переменные окружения

Плагин полностью интегрирован с Manifest v2 Hermes. Все настройки доступны как в графическом интерфейсе **Настройки → Плагины → hermes-laya-tools** (Hermes Desktop / WebUI), так и через конфигурационный файл `config.yaml` или переменные окружения `~/.hermes/.env`.

Изменения, сделанные в интерфейсе Hermes, сохраняются в `config.yaml` и автоматически применяются плагином на лету без перезапуска.

| Параметр в UI | Переменная .env | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| **Включен** | `LAYA_ENABLED` | `true` | Включение / отключение интеллектуальной маршрутизации Laya |
| **Режим работы** | `LAYA_MODE` | `active` | Режим работы: `active` (Top-10 выбор), `shadow` (только аудит) или `enrich_top3` / «Добавление топ 3» (стандартный список + топ-3 от Laya) |
| **Иерархическая маршрутизация** | `LAYA_HIERARCHICAL` | `true` | Двухуровневый выбор (категория -> релевантные инструменты) |
| **Лимит инструментов (Top-K)** | `LAYA_MAX_TOOLS` | `10` | Максимальное число инструментов в контексте модели |
| **URL сервиса Laya** | `LAYA_SIDECAR_URL` | `http://127.0.0.1:8787` | REST эндпоинт Sidecar инференс-сервера System 1 |
| **Таймаут Sidecar (мс)** | `LAYA_TIMEOUT_MS` | `5000` | Максимальное время ожидания ответа Laya (мс) |
| **Порог уверенности чата** | `LAYA_DIRECT_CHAT_THRESHOLD` | `0.75` | Защитный порог: инструменты отключаются только при уверенности ≥ 75% |
| **Всегда доступные инструменты** | `LAYA_ALWAYS_INCLUDE` | `""` | Список инструментов через запятую, гарантированно остающихся в топе |
| **Переразбить категории сейчас** | `LAYA_RECATEGORIZE_NOW` | `false` | Не поле формы: действие вынесено в кнопку на странице плагина (см. ниже); флаг остаётся доступным через `.env` / `config.yaml` |
| **Быстрый фильтр коротких фраз** | `LAYA_TRIVIAL_BYPASS` | `true` | Локальный фильтр коротких подтверждений (ок, да, спасибо) без сети (<1мс) |
| **Кэшировать повторы** | `LAYA_CACHE_REPEAT_ASKS` | `true` | Кэширование решений для повторяющихся инструкций (0 мс на повторах) |
| **Защита приватности логов** | `LAYA_PRIVACY_MODE` | `true` | Маскирование токенов, ключей и личных данных в журнале аудита |
| **Режим восстановления (Fallback)** | `LAYA_FALLBACK_MODE` | `pass-all` | Поведение при сбое: `pass-all` (сохранить все) или `strip-all` |
| **Уведомления в чате** | `LAYA_NOTIFY_IN_CHAT` | `true` | Выводить информационное сообщение в чат (в shadow всегда `false`) |
| **Уровень логирования** | `LAYA_LOG_LEVEL` | `INFO` | Детализация журнала аудита (`DEBUG`, `INFO`, `WARNING`, `ERROR`) |
| — | `LAYA_OFF` | — | Аппаратный Kill Switch (env или файл `~/.hermes/laya/LAYA_OFF`) |
| — | `LAYA_LOG_PATH` | `~/.hermes/logs/laya_requests.jsonl` | Путь к файлу журнала аудита запросов JSONL |
| — | `LAYA_CACHE_PATH` | `~/.hermes/cache/laya_categories.json` | Путь к кэшу категоризации инструментов |

## ➕ Режим «Добавление топ 3» (`LAYA_MODE=enrich_top3`)

Режим обогащения списка тулзов. Стандартный список инструментов, который Hermes передаёт модели, **не сокращается**: к нему добавляются топ-3 инструмента по версии Laya, если их ещё нет в стандартном списке.

- Поиск топ-3 устроен так же, как поиск топ-10:
  - **двухуровневая маршрутизация** (`hierarchical=true`): сначала Laya выбирает категорию, к которой относится нужный инструмент, затем выбирает топ-3 из этой категории (если в категории меньше трёх инструментов, пул добирается из следующих по вероятности категорий);
  - **плоская маршрутизация** (`hierarchical=false`): топ-3 выбираются из всего каталога инструментов.
- Инструменты, уже присутствующие в стандартном списке, повторно не добавляются.
- При сбое Laya и коротких подтверждениях (`ок`, `спасибо`) стандартный список остаётся нетронутым (`fallback_mode=strip-all` в этом режиме ничего не отключает).
- Включить можно в настройках («Режим работы» → «Добавление топ 3»), через `LAYA_MODE=top3` или командой `/laya top3`.

## 🔓 Интеграция с прогрессивным раскрытием инструментов Hermes (`tool_search`, `tool_describe`, `tool_call`)

В стандартном режиме Hermes скрывает отложенные (deferred), плагинные и MCP-инструменты за тремя мостовыми инструментами прогрессивного раскрытия:
- `tool_search` — поиск доступных инструментов по ключевым словам;
- `tool_describe` — получение полных JSON-схем выбранных инструментов;
- `tool_call` — вызов отложенных инструментов.

**hermes-laya-tools** обеспечивает бесшовную совместную работу с этим механизмом:
1. **Гарантированное присутствие bridge-инструментов**: `tool_search`, `tool_describe` и `tool_call` всегда добавляются в итоговый список инструментов для LLM во всех активных режимах (`active`, иерархическом, плоском, `enrich_top3`, а также при `direct_chat` и `trivial_bypass`), не занимая слоты `max_tools`.
2. **Контроль целостности при обновлениях Hermes**: плагин проверяет доступность стандартных bridge-инструментов Hermes (`verify_bridge_tools`). Если при обновлении Hermes они были переименованы или удалены, плагин фиксирует `ERROR` в логах и JSONL-аудите (`bridge_tools_missing`), отображает диагностику в `/laya status` и автоматически переходит в безопасный режим `fail-open` (передаёт полный список инструментов без фильтрации).
3. **Синхронизация `agent.valid_tool_names`**: при любом обновлении `agent.tools` плагин синхронно расширяет `agent.valid_tool_names`, чтобы валидатор Hermes (`turn_tool_validation.py`) корректно пропускал прямые вызовы инструментов, выбранных Laya.
4. **Автоматическое раскрытие полного каталога после вызова поисковых тулзов**: как только модель вызывает `tool_search`, `tool_describe`, `tool_call`, `manage_catalog` или `manage_connections` (либо обращается к скрытому инструменту через мост), плагин в `_on_post_tool_call` и на последующих ходах сессии (`bridge_unlocked`) открывает модели прямой доступ к полному несокращённому списку всех специализированных и базовых инструментов.

## ⚡ Кнопка переразбивки инструментов в UI настроек

В графическом интерфейсе **Настройки → Плагины → hermes-laya-tools** (Hermes Desktop, страница «Категоризация инструментов») доступна кнопка:
- **«⚡ Переразбить сейчас»** (поддерживается нативным расширением `desktop/plugin.js`, который нужно установить на машине с Hermes Desktop в `desktop-plugins/hermes-laya-tools/plugin.js`).
- При нажатии в рабочей сессии выполняется команда `/laya recategorize`: все установленные инструменты (Built-in + MCP) классифицируются через Laya Sidecar, сбрасывается суточный TTL кэша, а краткий отчёт (число категорий, количество тулзов) показывается во всплывающем уведомлении. Нужен хотя бы один открытый чат.
- Раньше это был переключатель в форме настроек; теперь это именно кнопка.

## 🚀 Установка в Hermes Agent

1. Скопируйте папку с плагином в каталог плагинов Hermes:
   ```bash
   cp -r hermes-laya-tools ~/.hermes/plugins/
   ```

2. Задайте настройки в файле `~/.hermes/.env`:
   ```env
   LAYA_URL=http://127.0.0.1:8787
   LAYA_MODE=shadow
   LAYA_MAX_TOOLS=10
   ```

3. Запустите Hermes CLI или перезапустите gateway:
   ```bash
   hermes
   ```

## 💬 Команды управления (`/laya`)

Плагин регистрирует нативную слэш-команду Hermes `/laya`:

- `/laya status` — текущий статус инференса Laya, режим работы, статус kill-switch, путь к логам и последнее решение.
- `/laya recategorize` — немедленная переразбивка всех доступных инструментов (Built-in + MCP) с выводом краткой сводки в чат.
- `/laya shadow` — переключение в режим Shadow (без перезапуска процесса).
- `/laya active` — переключение в активный режим маршрутизации.
- `/laya top3` — переключение в режим «Добавление топ 3».
- `/laya config` — вывод текущей конфигурации плагина со всеми параметрами.
- `/laya reload` — запрос hot-reload весов модели в Laya engine и перезагрузка параметров.
